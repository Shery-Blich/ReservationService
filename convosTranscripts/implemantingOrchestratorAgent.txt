● Why public partial class Program; is needed — it's not about giving the
  testing agent access to your business logic, it's plumbing required by the
  .NET tooling itself:

  WebApplicationFactory<TEntryPoint> (the harness plan.md specifies for the
  fake-TimeProvider throttle tests) is a generic class — it needs a type to know
  which compiled assembly/entry point to boot up in-process. With top-level
  statements, the compiler auto-generates a Program class, but marks it internal
  — invisible outside the API assembly. A test project in a different assembly
  literally cannot write WebApplicationFactory<Program> unless that class is
  exposed somehow.

  There are two ways to expose it:
  - [assembly: InternalsVisibleTo("...")] in the API project — this exposes
    everything internal (all internal classes, methods, fields) to the test
    assembly.
  - One line, public partial class Program;, at the bottom of Program.cs — this
    exposes only that one empty marker class (it has zero members; all the real
    code stays in top-level statements, which don't become part of the public
    surface).

  The second option is strictly narrower, so that's what I'll use. Either way,
  the testing agent never opens or reads any file under
  src/ReservationService.Api/ to write its tests — it works purely from
  plan.md's HTTP contract, talks to the app only via real HTTP through the
  factory's HttpClient, and the only thing it needs mechanically is a
  <ProjectReference> so the compiler can resolve Program as a type — not a
  source-code read. I'll wire both of these myself during scaffolding, before
  any agent touches the code.
