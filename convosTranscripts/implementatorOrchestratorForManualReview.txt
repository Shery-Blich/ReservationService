● Good catch to double check — moving the gate into ThrottleLatch doesn't change
  what prevents the ingest, only where the lock lives.

  Right now the semaphore just wraps the same section it already wraps: "check
  the latch → maybe open a DB transaction → decide 429 vs write-and-201."
  IngestService still owns that whole decision — validate the request, open the
  transaction, evaluate the counter, write the reservation row or not, commit.
  The semaphore's only job is to stop multiple concurrent requests for the same 
  supplier from all slipping past the "is it already blocked?" check at once
  before any of them has had a chance to actually mark it blocked.

  So folding it into ThrottleLatch just means: instead of IngestService holding
  a private static ConcurrentDictionary<string, SemaphoreSlim> itself,
  ThrottleLatch (already the singleton that owns the per-supplier "is this
  bucket blocked" state) also owns the per-supplier lock, since both are the
  same kind of per-supplier shared state and naturally belong together.
  IngestService would look something like:

  await using var gate = await throttleLatch.AcquireGateAsync(supplierId);
  if (throttleLatch.IsBlocked(supplierId, bucketId))
  {
      return 429;
  }
  // ...exact same DB transaction / write-or-reject logic as today, unchanged...

  IngestService still does 100% of the actual work inside that gated section —
  it's not handing control of the ingest decision to ThrottleLatch, just
  borrowing a per-supplier mutex from it. Nothing about "ingest acknowledging
  the throttle" changes; the 429-vs-201 decision, the DB transaction, and the
  reservation write all stay exactly where they are in IngestService.

  The only real benefit: IngestService (registered Scoped) no longer needs its
  own static field to share state across requests — that responsibility moves to
  ThrottleLatch, which is already a singleton built for exactly this kind of
  per-supplier shared state, and becomes independently unit-testable (you can
  fake IThrottleLatch in a test without touching real concurrency primitives).

  Does that answer it, or do you want to see the exact shape of AcquireGateAsync
  before I send this to a coder?
