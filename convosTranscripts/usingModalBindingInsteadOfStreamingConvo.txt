● Fixed. The ingest endpoint now uses ASP.NET Core's built-in JSON body model
  binding instead of manually reading the stream and calling
  JsonSerializer.DeserializeAsync:

  - IngestFeatureExtensions.cs: MapPost now takes IngestRequestBody body
    directly as a parameter instead of HttpContext + raw Stream.
  - IIngestService/IngestService: IngestAsync now accepts the already-bound
    IngestRequestBody instead of a Stream; removed the manual
    JsonSerializer.DeserializeAsync call, the JsonSerializerOptions field, and
    the try/catch (JsonException) block.
  - IngestRequestBody: made public (was internal), since it's now part of the
    endpoint's public binding signature.
  - New: ErrorHandling/MalformedJsonBodyExceptionHandler.cs: when model binding
    itself fails (malformed JSON, wrong field types like a numeric supplierId or
    string price), ASP.NET Core throws BadHttpRequestException — this
    IExceptionHandler catches that and returns the same 400 validation-problem
    shape the app used before, registered via AddExceptionHandler<>() in
    Program.cs.

  This was necessary because minimal APIs only auto-convert malformed-body JSON
  exceptions to a plain 400 when ThrowOnBadRequest is false (production); in
  Development (and under WebApplicationFactory in tests) it rethrows for
  diagnostics, which surfaced as a 500 until the handler was added. All 50
  integration tests pass.
